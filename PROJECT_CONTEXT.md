## Назначение

**Time To Go / «Время идти»** — кроссплатформенное Flutter-приложение для
христианской евангелизации. Оно помогает вести карточки людей, фиксировать
результаты служения, просматривать общую карту и свидетельства, а также
синхронизировать персональные данные с сервером.

Интерфейс русско-английский (по умолчанию русский), с системной, светлой и
тёмной темами. Визуальный стиль построен на Material 3; для Apple-платформ
есть специализированные Cupertino-подобные компоненты.

## Запуск и сборка

Для локальной разработки:

```bash
flutter pub get
flutter run
flutter analyze
```

По умолчанию API: `https://api.time.to.go.xn--80a6ad.space`. Его можно заменить:

```bash
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

Dockerfile собирает Flutter Web в release-режиме с production API, затем отдаёт
`build/web` через `nginx:alpine`. `docker-compose.yml` публикует порты 80/443,
подключает сертификаты Let's Encrypt и перезапускает контейнер автоматически.
Production-домен веб-приложения: `time.to.go.xn--80a6ad.space`.

Nginx перенаправляет HTTP на HTTPS, поддерживает клиентскую маршрутизацию через
`try_files ... /index.html`, отключает кэш для entry points и кэширует статические
ресурсы на год. Сертификаты ожидаются на хосте в `/etc/letsencrypt`.

## Зависимости и платформенные возможности

- `http` — REST API;
- `shared_preferences` — токен, настройки и офлайн-список;
- `path_provider` — файловый кэш аватара на нативных платформах;
- `flutter_map` + `latlong2` — карта и выбор координат;
- `geolocator` — получение текущей позиции;
- `image_picker` — выбор аватара;
- `url_launcher` — Telegram и телефонные ссылки;
- `intl` — RU/EN-форматирование дат.

Android запрашивает точную и приблизительную геолокацию. iOS описывает доступ к
геолокации и фотобиблиотеке в `Info.plist`. Веб-манифест и favicon присутствуют;
метаданные Web пока используют шаблонные `description` и title `time_to_go_app`.

## Архитектура приложения

`main()` инициализирует форматирование дат `ru_RU`/`en_US`, затем запускает
`TimeToGoApp`. Корневой state загружает тему, язык и JWT из `SharedPreferences`,
создаёт один `BackendApi` и показывает либо экран авторизации, либо `HomeScreen`.

Ключевые состояния:

- `AppLanguage`: `ru`, `en`;
- `AppThemeMode`: `system`, `light`, `dark`;
- `BelieverStage`: `interested`, `receivedJesus`, `joinedCommunity`,
  `baptised`, `evangelist`;
- `EvangelismMethod`: `fourSigns`, `jesusAtDoor`, `custom`.

Основной экран включает нижние разделы: главная/статистика, список людей,
методы евангелизации, карта и профиль. В настройках меняются тема и язык,
а также доступен вход/выход. Отдельные bottom sheet используются для входа,
редактирования профиля, добавления человека, выбора метода, даты и локации,
ввода и редактирования статистики, а также просмотра свидетельств.

### Поведение разделов

- **Главная:** свидетельство дня/лента свидетельств и общие показатели:
  услышавшие Евангелие и принявшие Иисуса. Данные берутся из публичного API.
- **Люди:** персональный список авторизованного пользователя; создание,
  изменение стадии и удаление. В офлайн-режиме работает локально.
- **Методы:** встроенные «4 знака» и «Иисус у двери» с изображениями;
  поддерживаются серверные пользовательские методы.
- **Карта:** загружает публичный список всех людей с координатами. Превью
  намеренно не показывает Telegram и телефон.
- **Профиль:** аккаунт сервера, аватар, имя, e-mail, описание, личная
  суммарная статистика, свидетельства и удаление аккаунта.

## Локальные данные и синхронизация

| Ключ/файл | Содержимое |
| --- | --- |
| `app_theme_mode` | индекс выбранной темы |
| `app_language` | `ru` или `en` |
| `api_access_token_v1` | JWT access token |
| `believers_v2` | JSON-список локальных `NewBeliever` |
| `cached_backend_user_v1` | JSON профиля для офлайн-доступа |
| `cached_avatar_path_v1` | путь к локальному аватару |
| `cached_avatar_url_v1` | URL версии кэшированного аватара |
| Documents/profile_avatar.jpg | бинарный кэш аватара на нативных ОС |

Без входа пользователь может продолжить работу офлайн. После регистрации
локальные карточки мигрируются на сервер в best-effort режиме. При успешном
входе локальный список заменяется данными `GET /believers/my`; при проблемах
с сетью сохраняются локальные данные и кэш профиля. Создание, смена стадии и
удаление сначала отражаются локально и затем пытаются синхронизироваться.

При logout токен и кэш профиля/аватара очищаются. `UserProfileCache` не
использует файловый кэш в Web и тихо оставляет прежний аватар при ошибке
загрузки.

## Модель человека

Локальная `NewBeliever` хранит `id`, возможный `remoteId`, имя, Telegram,
телефон, заметку, текст свидетельства, метод, дату создания, стадию,
координаты и название места. Имя — единственное обязательное поле формы;
Telegram и телефон нормализуются и валидируются. Телефон сохраняется в
международном виде, Telegram — как `@handle`.

Перед отправкой серверу поля преобразуются к контракту:

| Поле API | Смысл |
| --- | --- |
| `name` | обязательное имя |
| `telegram`, `phone_number` | необязательные контакты |
| `met_at` | дата `YYYY-MM-DD` |
| `stage` | одно из пяти значений выше |
| `method_id` | доступный серверный метод |
| `note`, `testimony` | необязательные тексты |
| `latitude`, `longitude` | координаты |

Стадия `interested` означает интерес к вере; остальные стадии считаются
принявшими Иисуса в статистике сервера.

## Backend API

Базовые адреса:

- production: `https://api.time.to.go.xn--80a6ad.space`;
- local: `http://127.0.0.1:8000`;
- Swagger: `https://api.time.to.go.xn--80a6ad.space/docs`.

Все запросы — JSON, кроме загрузки аватара (`multipart/form-data`).
`BackendApi` автоматически добавляет `Authorization: Bearer <token>`, если
токен есть; методы, требующие авторизации, отклоняют запрос без него локально.
Нестандартные статусы превращаются в `BackendApiException` с HTTP-кодом,
сообщением сервера (`detail`/`message`) и разобранным телом.

### Авторизация и профиль

| Метод | Доступ | Назначение |
| --- | --- | --- |
| `GET /` | public | health: `{ "status": "success" }` |
| `POST /auth/register` | public | регистрация: name, email, password |
| `POST /auth/login` | public | возвращает `access_token` |
| `POST /auth/refresh` | public | обновляет ещё действующий JWT |
| `GET /auth/me` | bearer | текущий пользователь |
| `PATCH /auth/me` | bearer | частично меняет `name`, `about` |
| `DELETE /auth/me` | bearer | удаляет аккаунт и все его данные, `204` |
| `POST /auth/me/avatar` | bearer | поле multipart `avatar`, возвращает User |

JWT живёт 7 дней. Refresh работает только до истечения токена; после `401`
пользователь должен войти вновь. Пароль ограничен 72 байтами UTF-8. Аватар
может быть JPEG/PNG/WebP/GIF/HEIC/HEIF до 5 MB; `avatar_url` может быть
относительным `/uploads/...` и приводится приложением к полному URL.

### Методы евангелизации и люди

| Метод | Доступ | Назначение |
| --- | --- | --- |
| `GET /methods` | bearer | стандартные и собственные методы |
| `POST /methods` | bearer | создать пользовательский метод |
| `POST /believers` | bearer | создать карточку, `201` |
| `GET /believers` и `/believers/my` | bearer | только собственные, по убыванию даты |
| `GET /believers/{id}` | bearer | собственная карточка |
| `PATCH /believers/{id}` | bearer | частично изменить собственную карточку |
| `DELETE /believers/{id}` | bearer | удалить, `204` |
| `GET /believers/all` | public | все карточки |
| `GET /believers/latest` | public | максимум 20; фильтры `date_from`, `date_to` |
| `GET /believers/testimonies` | public | все объединённые свидетельства |
| `GET /believers/testimony-of-day` | public | одно свидетельство, параметр `day` опционален |
| `GET /believers/stats/accepted-jesus-count` | public | `{ "count": n }` |

Стандартные методы: `4 знака`, `Иисус у двери`. Пользовательский метод
уникален в пределах пользователя. Публичные ответы людей включают `owner`
(id, name, avatar_url). Единая модель свидетельства может прийти из `believer`
или `outreach` и содержит `testimony`, `owner`, а для человека ещё
`believer_name` и `met_at`.

### Суммарная статистика служения

У каждого пользователя ровно одна накопительная запись. Старые endpoints с
ID статистики больше не применяются.

| Метод | Доступ | Назначение |
| --- | --- | --- |
| `GET /outreach-statistics/summary?type=general\|personal` | public / bearer для personal | агрегированная сводка |
| `GET /outreach-statistics/me` | bearer | личная запись; создаёт нулевую при отсутствии |
| `POST /outreach-statistics/add` | bearer | прибавляет значения к итогам |
| `PATCH /outreach-statistics/me` | bearer | задаёт отдельные итоги напрямую; удаляет свидетельство по ID |
| `POST /outreach-statistics/reset` | bearer | обнуляет счётчики |
| `GET /outreach-statistics/all` | public | одна запись на пользователя, включая User |

Поля записи: `gospels_told`, `salvation_prayed_unreachable`,
`scriptures_distributed`, `fathers_letters_distributed`,
`healings_deliverances` (все целые >= 0) и `testimonies` — список объектов
`{id, text}`. При добавлении допускается один текст `testimony`; при PATCH
удаление выполняется полем `delete_testimony_id`.

Сводка возвращает `total_heard_gospel`, `total_saved`, `contacts_taken`,
`scriptures_distributed`, `fathers_letters_distributed`,
`healings_deliverances`. Первые два объединяют карточки людей и накопленные
счётчики; контакты — число людей с телефоном или Telegram.

## Технический долг и предосторожности

- `lib/main.dart` монолитен; при крупных изменениях лучше выносить модели,
  экраны, виджеты и локализацию постепенно, не меняя поведение.
- Линтер подключает `flutter_lints`; в прошлой проверке отмечались главным
  образом info-предупреждения об устаревшем `withOpacity` и некоторых
  значениях полей формы.
- Не добавлять секреты или JWT в репозиторий. `API_ACCESS_TOKEN` допустим
  только как временный `--dart-define` для запуска.
- Для изменений API сначала сверять реальный Swagger: контракт ниже основан
  на последнем сохранённом руководстве, а сервер — внешняя развивающаяся
  система.
- Карта и публичные свидетельства намеренно доступны без авторизации;
  контакты в предпросмотре карты скрыты из соображений приватности.
